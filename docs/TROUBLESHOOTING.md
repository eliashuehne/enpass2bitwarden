# Troubleshooting

## "cannot unlock vault — wrong master password or not an Enpass v6 vault"

- Wrong master password (most common). The password is case-sensitive.
- Enpass 5 or older vaults use a different format — this tool supports Enpass 6+ only.
- If your vault uses a **keyfile** in addition to the master password, it is not
  supported yet (`have_keyfile: 1` in vault.json).

## `.enpassattach` files not found

External attachments live in an `Enpass/` folder next to `vault.enpassdb` —
regardless of whether your vault is synced via WebDAV, a cloud drive, a NAS,
or stays local. Copy that folder (if it exists) next to the vault file before
running `decrypt`:

```
vault.enpassdb
vault.json
Enpass/
  0bd285a1-....enpassattach
  ...
```

The tool looks in `<vault dir>/` and `<vault dir>/Enpass/`.

## Passkey doesn't appear when clicking "Sign in with passkey"

Open the Bitwarden extension's background console:
`chrome://extensions` → Developer mode → Bitwarden → "service worker".

| Console error | Cause |
|---|---|
| `importKey ... Algorithm: Unrecognized name` | `keyAlgorithm` must be `"ECDSA"`, not the COSE name `"ES256"` — re-apply credentials generated by this tool |
| Nothing offered, page times out with AbortError | `credentialId` must carry the `b64.` prefix — credentials applied by hand are often missing it |

Credentials produced by this tool always have both fields correct. If you
applied them manually, re-check these two fields first.

## "Authentication failed" on the website after selecting the passkey

The site rejected the assertion. Verify:

1. The extension is unlocked and has vault access enabled for the site.
2. Log out and back into the extension after applying new credentials — it
   caches aggressively.
3. Credential IDs and user handles were preserved byte-for-byte; compare with
   the values in `dump.json`.

## bw CLI errors

- `BW_SESSION not set` → `export BW_SESSION=$(bw unlock --raw)`
- Concurrent edits fail with "client copy out of date" → run `bw sync`, then retry.
- Older `bw` versions require `--itemid <id>` for attachment operations; this
  tool passes the flag automatically.
